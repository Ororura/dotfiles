# Fedora GNOME + Niri: перенос рабочего окружения

Снимок проверенного окружения от 20 октября 2026 года: Fedora 44,
Niri 26.04, Waybar 0.15, Ghostty 1.3.1, Yazi 26.9.1, OpenRGB 1.1.
GNOME и GDM сохраняются. Настройки панели, меню, раскладки, шрифтов,
обоев, уведомлений, блокировки, мониторинга и подсветки включены в репозиторий.

## После переустановки этого компьютера

Сначала установите Fedora Workstation GNOME и рабочий NVIDIA-драйвер.
Установщик dotfiles не устанавливает видеодрайвер, не меняет загрузчик,
initramfs, display manager или глобальные GSettings.

```bash
sudo dnf install -y git bash python3
git clone https://github.com/Ororura/dotfiles.git ~/.dotfiles
cd ~/.dotfiles

# Просмотр действий: без загрузок и изменений системы.
bash install.sh --full --dnf --nvim --ghostty --niri \
  --niri-profile=ororura-desktop --niri-rgb --dry-run

# Восстановить терминальные настройки и весь рабочий стол.
bash install.sh --full --dnf --nvim --ghostty --niri \
  --niri-profile=ororura-desktop --niri-rgb
```

`--full` восстанавливает Zsh, Oh My Zsh, Powerlevel10k и плагины средствами
существующего установщика. Он не меняет login shell автоматически.
Java/Node/Docker, IDE и личные данные устанавливаются/восстанавливаются отдельно.
Ключи SSH, токены, пароли, keyring, браузерные профили и данные Docker сюда
не переносились.

После установки самостоятельно выйдите из графического сеанса. В GDM выберите
пользователя, затем шестерёнку и **Niri**. Для возвращения выберите **GNOME**.
Установщик не завершает сеанс и не перезагружает компьютер.

## Только рабочий стол / другой компьютер

```bash
cd ~/.dotfiles
# Этот ПК, без повторной установки Zsh/Neovim:
bash scripts/install-niri.sh --packages --profile ororura-desktop --rgb

# Другой ПК: автоматические режимы мониторов, без аппаратного RGB.
bash scripts/install-niri.sh --packages

# Только подключить конфигурации к уже установленным программам:
bash scripts/install-niri.sh --profile ororura-desktop --rgb
```

Без `--packages` нет DNF и загрузок. Без `--rgb` меню подсветки скрыто,
а профиль доступа к оборудованию не устанавливается. Профиль `generic`
не назначает видеовыходы, разрешения и частоты; Niri выбирает их автоматически.
`ororura-desktop` хранит DP-1 2560×1440@165.001 и DP-2 1920×1080@144.001,
расположение экранов и привязку именованных пространств к DP-1.

Поддерживается стандартное расположение `~/.config`. На других дистрибутивах
зависимости нужно установить самостоятельно; `--packages` рассчитан на Fedora.
Конфигурация требует возможностей Niri 26.04, включая include и blur.
Установщик запускает `niri validate` над подготовленной конфигурацией до
замены файлов; при неподдерживаемом синтаксисе перенос отменяется.

## Где редактировать

| Каталог в репозитории | Что хранится | Устанавливается в |
| --- | --- | --- |
| `niri/` | KDL, клавиши, скрипты, btop, обои | `~/.config/niri/` |
| `waybar/` | Панель, CSS, мониторинг и погода СПб | `~/.config/waybar/` |
| `desktop/templates/fuzzel.ini` | Launcher и оформление меню | `~/.config/fuzzel/fuzzel.ini` |
| `mako/`, `swaylock/`, `yazi/` | Уведомления, блокировка, файловый менеджер | соответствующие каталоги `~/.config/` |
| `systemd/user/` | Службы только для Niri | `~/.config/systemd/user/` |
| `desktop/profiles/ororura-desktop/` | Мониторы и проверенный RGB | выборочно в `~/.config/niri/` |
| `desktop/templates/` | Файлы с путями текущего пользователя | Ghostty overlay, Fuzzel, desktop-файл Yazi |
| `desktop/fonts/` | Используемые начертания Nerd Font и OFL | `~/.local/share/fonts/` |
| `desktop/assets.lock.json` | URL, версии, SHA256 Yazi/OpenRGB | загрузки через `--packages` |
| `desktop/packages-*-fedora.txt` | Необходимые RPM | официальные Fedora/updates |

Обычные конфигурации и скрипты подключены **символическими ссылками**:
изменение такого файла через `~/.config` сразу видно в `git diff`.
Корневой `config.kdl` копируется, чтобы относительные include использовали
установленные файлы выбранного профиля. Файлы шаблонов генерируются для
текущего `$HOME`. OpenRGB JSON копируется: программа может изменять его,
и её состояние не должно записываться в Git.

Менять мониторы этого ПК: `desktop/profiles/ororura-desktop/outputs.kdl`.
После изменения профиля, корневого KDL или шаблонов повторите установку
с теми же `--profile`/`--rgb`. Остальные ссылки применяют правки сразу,
с учётом обычной перезагрузки конфигурации соответствующей программы.

Кэши, логи, `__pycache__`, история clipboard, последнее RGB-состояние и
режим презентации не включены. Старые привязанные к каталогу Codex скрипты
отката заменены переносимым восстановлением установщика. Исходные резервные
копии той настройки остаются на старой системе и не требуются для установки.

## Службы и GNOME

Используются пакетные `niri-session`, `niri.desktop`, `niri.service`,
`waybar.service`, `mako.service` и `niri-portals.conf`. Собственные службы
панели и compositor не создаются. Зависимости добавляются только в
`niri.service.wants`, с `PartOf=niri.service` и проверкой рабочего стола.
RGB-служба запускается по запросу и в `.wants` не добавляется.

Переиспользуются NetworkManager, PipeWire/WirePlumber, GNOME Keyring,
GNOME/GTK portals, Nautilus и tuned/tuned-ppd. Polkit-agent MATE запускается
только в Niri. Тема Breeze-Dark задаётся только окружению Niri/его служб,
без изменения dconf GNOME. Xwayland Video Bridge исключён из автозапуска
Niri; остальные рабочие столы сохраняют его обычное поведение при наличии.

Установщик перечитывает пользовательские units, но не запускает и не
перезапускает компоненты текущего сеанса. Их холодный запуск проверяется при
следующем входе в Niri. Новые зависимости устанавливаются только с
`--packages`, из `fedora` и `updates`, без COPR и слабых зависимостей.

## RGB именно этого ПК

Профиль: Gigabyte B550 AORUS PRO V2, Corsair Commander CORE / H115i Elite
Capellix и GPU PCI 10de:21c4 / 1458:4020. При установке проверяются плата и GPU.
Переключение доступно через **Super+S → Подсветка** или шестерёнку Waybar.
Включение — Mocha Blue `#89B4FA`, выключение — `#000000`.

В OpenRGB разрешены только два проверенных USB-драйвера; клиент не выполняет
аппаратное обнаружение. Слушается только `127.0.0.1:6743`. Размер RGB-пакета
Corsair — 34 позиции на порт, физические ML140 имеют по 8 светодиодов.
ARGB использует аппаратный Static на полном диапазоне канала (1024),
что не является числом реально подключённых светодиодов.

GPU обслуживает отдельный `rgb_gpu.py`: находит **единственную** карту с
точными PCI ID и её NVIDIA I²C-адаптер №1, затем проверяет сигнатуру
контроллера по единственному адресу 0x47. Номер PCI-слота/шины не зашит:
после переустановки или перестановки карты он определяется через sysfs.
Проверенный ответ — AB 14 01 00. Команды цвета взяты из OpenRGB 1.1;
сканирования шин, EEPROM-записи, управления частотами/охлаждением нет.

Нужны устройства `/dev/i2c-*` и пользовательский доступ к HID/I²C.
Если после переустановки их нет, проверьте наличие модуля `i2c-dev` и правила
`openrgb-udev-rules` отдельно. Установщик не добавляет модули ядра и не
применяет низкоуровневые команды RGB при переносе файлов.

OpenRGB 1.1 скачивается переносимым AppImage без KDE/KF5 RPM-зависимостей.
Архив и извлечённый бинарник проверяются по закреплённым SHA256.
Yazi также проверяется по SHA256 релизного архива и обоих бинарников.
Воспроизводимость привязана к закреплённым версиям; скачивание требует
доступности указанных официальных релизов. Автоматический bootstrap этих
двух программ предусмотрен для Linux x86_64.

## Проверка после входа

```bash
~/.config/niri/scripts/first-login-check
~/.config/niri/scripts/shortcuts.py --list
niri validate
systemctl --user status niri.service waybar.service mako.service niri-idle.service
journalctl --user -b -u niri.service -u waybar.service -u niri-rgb.service
```

Вручную проверьте разблокировку паролем, звук/микрофон, EN/RU, буфер,
Nautilus/порталы, демонстрацию экрана, X11 IDE и оба монитора. Для RGB
проверьте реальное свечение: программная таблица цветов не измеряет свет.
Для Niri/NVIDIA установщик не добавляет глобальные переменные и не
применяет GLVidHeapReuseRatio автоматически.

Основные сочетания: Super+Enter — Ghostty; Super+D — launcher;
Super+Space — EN/RU; Super+H/J/K/L — фокус; Super+Shift+H/J/K — перемещение;
Super+Shift+L — блокировка; Super+S — настройки; Super+E — Yazi;
Super+Shift+P — презентация; Super+F1 — полный список сочетаний.
Super+1…5 — именованные пространства, Super+6…9 — динамические.

## Резервная копия и откат

Каждый реальный перенос создаёт `~/.dotfiles-backups/niri-ДАТА-ID/` с
исходными файлами/ссылками и `manifest.json`. Повторная установка без
изменений не создаёт новую копию. При ошибке применения прежние файлы
возвращаются автоматически. Установщик не удаляет посторонние настройки
из каталогов приложений. Существующие ссылки на целые каталоги требуют
отдельной миграции: запись через них отклоняется до изменения файлов.

```bash
python3 ~/.dotfiles/scripts/install_niri.py --restore \
  ~/.dotfiles-backups/niri-ДАТА-ID
# Альтернативный вызов того же восстановления:
~/.config/niri/scripts/restore-original.py ~/.dotfiles-backups/niri-ДАТА-ID
```

Перед откатом текущее состояние тоже сохраняется. Для применения старых
служб повторно войдите в сеанс. RPM не удаляются, аппаратный RGB-эффект
не восстанавливается. Для возврата в GNOME достаточно выбрать GNOME в GDM.

Перед переустановкой сохраните **репозиторий целиком** в GitHub или на внешний
диск. Локальные изменения без commit/push не появятся в новом клоне.
Для проверки содержимого: `git status --short` и `git diff`.

## Проверки репозитория

```bash
python3 scripts/check-desktop.py
python3 -m unittest discover -s tests -v
```

Тестируются перенос в новый HOME с другим именем и пробелом в пути,
dry-run, повторная установка, сохранение исходных файлов и прав, откат,
защита ссылок на каталоги, отказ при ошибке валидации и повреждённой загрузке.
Полная установка RPM и первый вход на чистой Fedora требуют отдельной
проверки; тесты не имитируют графическое окружение целиком.
